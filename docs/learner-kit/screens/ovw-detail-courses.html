Same reasoning as the tracker's single-activity card, applied to a different component: there the timeline had no sequence to draw, here the percentage has only two values it can ever hold, so "0%" or "100%" is noise where the activity's own name and state are the answer. Drawn imageless like every compact card, and with two independent link targets: the outer <a> around the name, badge and state strip goes to the course; "Go to activity" is a second, separate <a> below it, to the activity itself — not a <span> nested inside the first link, which is what this card used to be. How the states interact with the enrolment filter enrollmentfilter
Filter (cascade: competency → template → site)What survives to the paneWhich states can appear
all — the site defaultevery visible linked courseAll three, and locked is common: a course the learner has no relation to says so, and the enrol state offers the way in.
enrolledany enrolment record, including future-dated and suspendedMostly locked with a date — a future-dated enrolment is exactly the "Enrolment opens" case.
activeactively enrolled onlyChiefly open. Locked is rare but real (an access restriction); enrol never appears.
enrolledorselfenrolled, plus what the viewer could self-enrol intoThe enrol state is precisely what this filter lets through beyond "enrolled".
The filter runs server-side inside the courses web service, so it decides membership before any state is computed. The two settings are complementary, not redundant: the filter answers "should this card exist at all", the state answers "what can the learner do with it".
