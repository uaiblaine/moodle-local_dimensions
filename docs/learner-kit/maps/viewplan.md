# Field map — `OVW` · Full Plan Overview (`view-plan.php`)

"Full Plan Overview" mode: every competency in a learning plan, laid out either as an accordion
(list mode) or as a card grid whose cards open a detail modal. Renderable
`view_plan_summary_page` → `view_plan_summary.mustache`. Each item's **expanded detail** is built
client-side by `accordion.js` from three plugin web services, called on first open:
`local_dimensions_get_user_competency_summary_in_plan` (Rating / Description / Evidence) +
`local_dimensions_get_competency_courses` (linked courses + their activities) +
`local_dimensions_get_competency_rule_data` (Rules tab, lazy on first tab activation). The hero,
the toolbar, the chip panel and the accordion shell are server-rendered; sorting, filtering,
favouriting and the layout swap all act on the already-loaded rows with no re-fetch.

## Dropped

- **The `enrollmentfilter` gate on the Rules tab's child list.** Retired in planning, not merely
  unbuilt: a child with no accessible course is already handled by `view-competency.php` one level
  down, and filtering here would have corrupted the points arithmetic behind
  `OVW-RULES-PROGRESS`.
- **A grey "Attach evidence" badge for `OUTCOME_EVIDENCE`.** It is core's DB default, so badging
  it would mark nearly every card instead of the few that decide anything. See `OVW-CRS-OUTCOME`.
- **A label-driven pane title ("Linked {label} & activities", `OVW-CRS-TITLE`).** Structurally
  foreclosed: there is no section heading left to retitle. The pane's name lives on the tab, as
  `related_content` ("Related content"), which retired the last learner-side consumer of the
  competency label.
- **A `showevidencecounts` admin setting.** A row count needs no administrative control; the
  journey count ships ungated. See `OVW-EVID-COUNTS`.
- **A "Recently updated" sort option.** The shipped set is Plan order / Name / Completed first /
  Favourites first. See `OVW-SORT`.
- **A plugin write web service for the favourite toggle.** Resolved differently rather than
  dropped from the product: the star writes through core's `setUserPreference`, because the plugin
  owns no tables. See `OVW-FAV`.
- **Grid mode as a `view` request parameter.** Resolved differently: the layout is a stored user
  preference and a client-side class swap, so it is not URL-addressable. See `OVW-VIEW`.
