Tokens — Learner views

The learner views used to inline a Material/Google skin, then a value-for-value Moodle DS palette written as literals. Both are gone. Every colour on these screens now reads a --local-dimensions-* token declared once on bare :root, so the same markup renders light or dark according to the host page and never according to the plugin. The --lk-* names below are this kit's shorthand for those tokens; the shipped stylesheet declares only the frankenstyle ones. The historical record of the first migration is in token-migration.md.

What changed, and why the columns below are two views of one thing

30 of the 34 tokens are written var(--bs-NEW, var(--BS4-OLD, #literal)). Moodle 4.5 declares none of those --bs-* names and Moodle 5.1/5.2 declare none of the Bootstrap 4 legacy names, so exactly one rung resolves per branch. Moodle 5.1/5.2 already compile a full [data-bs-theme="dark"] token block, so those 30 are dark-correct with no dark rule at all — the dark column is core's own measured output, not a second palette this plugin maintains. Only shadow, scrim and favourite carry a plugin-authored dark value, and they are the entire contents of the plugin's one activation rule.

Every value the old version of this page listed is now unreachable as a literal. #f4f5f7, #212529, #6c757d, #0a5aa0, #cfe2ff, #198754, #e5a100, #fff3cd, #664d03, #ffc107 and #ff922b are no longer written as a value anywhere in styles.css — one of them, #198754, survives once inside a comment recording why a candidate replacement measured worse on a dark page. The same is true of every one of the loose greys that page listed as deliberately un-normalised — #333, #e5e0e0, #f0f0f0, #f1f3f5, #8da1b6, #ccc — and the Stripe-style shadow tints. The search focus glow that page recorded as the one survivor of the Material skin, rgb(26 115 232 / 15%), is gone too: .local-dimensions-search-input:focus now draws outline: 2px solid var(--local-dimensions-focus-ring) at outline-offset: 2px over an accent border, with no glow at all. A box-shadow was never a legitimate focus indicator — Windows High Contrast Mode does not render one.

The rules orange — retired, not kept

This page used to flag #fd7e14 as a deliberate brand accent for "how a competency is earned", kept across nine rules. That decision was reversed. Every rules surface now speaks the warning tone family, so the learner views and the hub say the same thing the same way, and each surface carries its tone's own border exactly as core's .alert-warning does: the progress fill and the rules note are warning-ink, the required tag and the stale-evidence callout are warning-ink on warning-tint inside a warning-edge, and the "rated, not yet complete" accordion rail is warning-ink. The amber #e5a100 that rail used to carry is gone with it.

Orange survives in exactly one role, the favourites star, and it is one of the three tokens the plugin still owns outright: #e8590c light, #fd7e14 dark. It needs a plugin-authored dark value because no single star hue clears 3:1 against both #fff and #343a40 — core's own --bs-warning measures 1.95:1 on white. The star also no longer carries its state in colour alone: it swaps glyph between fa-star and fa-star-o, which is WCAG 1.4.1 and is pinned by a test.

Two rules the tokens cannot enforce by themselves

surface-insetA platter a control sits in, not a ground for coloured ink. In dark, accent and brand-ink measure 4.50:1 on it and danger-ink 4.20:1 — core's own values against core's own surface. Coloured ink belongs on surface or surface-alt; ink, ink-muted, ink-strong, success-ink, warning-ink, info-ink and neutral-ink are all fine there. The active chip label solves this by sitting on the indicator pill, which paints surface. ink-faintInactive-control text and placeholders only. It is 2.70:1 on surface-inset in light mode and rides WCAG 1.4.3's incidental exception, which covers text in an inactive component and nothing else — never a border, never a fill, never an icon.

Both are enforced, not merely written down: test_no_low_contrast_ink_on_the_inset_surface resolves the effective background through a selector-ancestry map, so the ancestor-background / descendant-colour split cannot slip past it, and test_ink_faint_is_only_inactive_text reddens on a border or a caption drawn in it.
