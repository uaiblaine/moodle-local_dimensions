The house wrapper · amd/src/central/toast.js
No hub module imports core/toast directly: they all go through local_dimensions/central/toast, which is thin on purpose — export const add = (message, configuration) => coreAdd(message, {closeButton: true, ...configuration}); (toast.js:39), with addToastRegion merely re-exported (:41). The only decision it imposes is the close button by default — which is why every toast drawn above carries the ×. The reason: a repeated action stacks several confirmations that hide themselves, and whoever repeated it wants to dismiss them at once instead of waiting out each one's 4s. It is core's own btn-close (Moodle 4.5+), and any core/toast option still overrides the default.

The house pattern, and why it exists. A toast fired from inside a core/modal would land behind it: the page's .toast-wrapper is z-index:1051 and the modal is 1055. So, on ModalEvents.shown, the modal hosts its own region — addToastRegion(modal.getBody()[0]) — and the toast renders above the dialog, with no global z-index override. Core removes the region itself on close (removeToastRegion), so there is no leak.
The host is the modal-host, always on shown and always with .catch(notifyError): competency_links.js:911-914 (courses and activities), participants_manager.js:233-236 (participants), related_competencies.js:266-269 (related competencies) and frameworks.js:315-316 (export). They are 4 of the hub's 17 modal-construction points — the others fire no toast from inside. Modules that only mount() inside those modals do not add a region of their own: cohort_manager.js:34 and participants_users.js:32 import only add, and write into the host's region.
Paired with the flash. For an in-place change (a row added/edited without reloading the list), the toast comes with a flash of the affected row — the single helper central/flash.js (flashRow, :34-48) — so the confirmation appears where the user is looking, not only in the corner. It reads the duration from the --mds-motion-flash token (1500ms) via getComputedStyle, animates with the WAAPI (#fff3cd → transparent, ease-out) and does nothing under prefers-reduced-motion — the flash is redundant confirmation, the toast has already said it. Six modules import the helper: structure, plans, competency_links, enrol_methods, roles_manager and related_competencies. <select>/inputs built in JS need an id or a name, otherwise the browser logs an autofill warning.
