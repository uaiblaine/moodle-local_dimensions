The control is core's filemanager, added with addElement('filemanager', …) plus one addHelpButton per field (picture_manager.php:144-155). The drawing above is the widget's shape: the toolbar, the drag-and-drop area and the file grid are core's, and so are that frame's labels — the kit does not fix their wording.
The only numbers the plugin chooses come from get_filemanager_options() (picture_manager.php:100-106): maxbytes 10485760 (10 MB), maxfiles 1, subdirs 0, accepted_types web_image.
Labels and order, casing included: Background image (custombgimage) first and Card image (customcard) second, in the order add_all_filemanagers_to_form() adds them (picture_manager.php:163-165); the label and the help text come from the same lang key (:146 picks the key, :150 uses it as the label and :154 uses it as the help).
The two dropzones exist only in built-in mode. competency_handler::instance_form_definition() only calls the picture_manager when is_builtin_mode() (competency_handler.php:173-175) — that is, when the image mode is not the external one (picture_manager.php:75-82). In external mode the images become picture custom fields (helper.php:473-478) and the row is drawn by that plugin, not by this kit. Because the filemanager pair is appended after the last category, it lands inside the Look section — see the Form section card.
