Focus is an outline, not a halo. The shipped pattern is outline: 2px solid #0f6cbf (or var(--bs-primary, #0f6cbf)) with outline-offset: 27 :focus-visible rules in styles.css write exactly that, plus 3 at 3px for large targets; the offset is 2px outside (19×) and -2px inside (11×) when the target touches the container's edge. No rule uses box-shadow: 0 0 0 3px as a ring — blue-200 (#9fc4e5) appears only as a hover border (:6291, :6652).
secondary is the only unsaturated fill — grey with adaptive text (--mds-text-default), so it needs a dark variant: default/hover become dark greys under prefers-color-scheme:dark, otherwise it renders white on light grey. primary and danger are saturated fills with fixed white text — the same reading in both schemes, no variant. The swatch above consumes the real token (not the surface), so the card demonstrates what it claims. Real coverage: blue-500 has 90 occurrences and blue-600 5; blue-700, red-500 and red-600 have zero — the hub draws no danger button of its own, it uses Boost's .btn-outline-danger.

Motion — the four tokens styles.css :root declares
fast 150ms · hover, focus, colour base 250ms · layout, tab indicator flash 1500ms · in-place confirmation
Hover the first two to feel 150ms against 250ms; flash does not transition — the JS is what fires it. A single easing --mds-motion-ease = cubic-bezier(0.4,0,0.2,1) (Material standard). fast matches Bootstrap's .15s. Under prefers-reduced-motion both transitions disappear — here in the card and in the shipped code too, where every rule that uses the tokens carries its own clause (e.g. styles.css:7267-7271).

What the code actually declares and consumes
  • styles.css :root (:29-34) declares exactly five custom properties: --mds-motion-fast, --mds-motion-base, --mds-motion-flash, --mds-motion-ease and --mds-loading-min-height. Everything else on this page is the kit's vocabulary: the values match Boost, but the shipped CSS writes literals.
  • Verified consumers: --mds-motion-fast on the modal header's chip (:4944), --mds-motion-base on the tab indicator (:7244), --mds-loading-min-height on the busy cover (:4030).
  • --mds-motion-flash is read by JS, not by CSS: central/flash.js:43 does getComputedStyle(el).getPropertyValue('--mds-motion-flash') and passes the duration to the WAAPI, with a 1500 fallback. The helper is a single one and replaced ten inline copies across six hub modules; today it is imported by structure, plans, competency_links, enrol_methods, roles_manager and related_competencies.
  • Adoption scope: new or reworked surfaces. Retro-tokenising the whole shipped CSS fights the less-code rule, so the divergence between "the kit speaks in tokens" and "the CSS writes literals" is deliberate, not debt.
  • Semantic --mds-* naming (primitive→semantic): when the React MDS lands (Moodle 5.3 LTS), the migration becomes a rename, not a redesign.
