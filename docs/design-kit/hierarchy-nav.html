The active context button is solid blue, not grey: the pair is a btn-group in which the active one takes btn-primary and the other btn-outline-secondary (contextbar.mustache:68 and :71). No rule in styles.css repaints that pair — there are only two rules for the bar, both of them category-wrapper layout (:7222-7230).
The hidden-categories switch only appears when a hidden category is reachable: contextbar.php:108-126 builds hiddencatstoggle as null when there is none, and it is born on if the selected category is itself hidden (otherwise the context would vanish from the selector). In System mode it is hidden (contextbar.mustache:75-79). It is the shared partial central/showhidden_toggle, the same pill as the three tabs; the label is central_bar_showhiddencategories.
The counter swaps its noun per tab, and the noun includes "in this context": central_frameworks = "structures in this context" and central_plans = "plans in this context" (both lower-case, both travel in the HTML and the client hides the one that does not apply — contextbar.mustache:94-99). The switching is done by renderCounter() (context.js:103-119) from activeMode() (:68-71), which only returns plans in the plans pane. The per-category count travels in the <option> as {name} ({count}) (contextbar.mustache:89) and is rewritten on the client with the active mode's count (context.js:126-132).
The Refresh button reloads the active pane, not the bar: it sits in the bar's ms-auto (contextbar.mustache:101-105, core string refresh) and calls reloadPane() spinning its own icon, with a finally that re-enables it and returns focus (context.js:206-230). The counter's number is not resynced by it — the bar lives outside the panes and is not re-rendered; the debt is recorded in maps/bar-contextbar.md.

The active tab's indicator is box-shadow: inset 0 -2px 0 var(--bs-primary, #0f6cbf) — that is what is painted above, not a caption (styles.css:7611-7614). The base zeroes the border and transitions box-shadow and color with --mds-motion-base/--mds-motion-ease (:7239-7245), with prefers-reduced-motion switching the transition off (:7653-7657). Same shape as format_mtube's indicator, where the idea came from.
These are the labels, and the naming is inverted: the pane whose shortname is structure shows Competencies (managecompetencies_structure) and frameworks shows Structures (central_frameworks_tab); the third uses learningplans (central.php:99-103). The render order is that of the loop at central.php:114: frameworks, structure, plans.
Where the icon enters: central.php assembles $tabicons (:108-112) and glues an <i class="fa fa-… me-1" aria-hidden="true"> onto the displayname inside the loop (:122, :125); core/dynamic_tabs.mustache triple-stashes displayname, so the icon enters through the label and nothing changes in the core template (the page renders core/dynamic_tabs directly at central.php:146). The glyphs: fa-sitemap (Structures), fa-crosshairs (Competencies), fa-graduation-cap (Plans) — the SVGs above merely stand in for Font Awesome, which this preview does not load.
Scope: the rule lives under .local-dimensions-central-page .dynamictabs .nav-tabs .nav-link (styles.css:7587) — the <body> class (central.php:57) confines the restyle to the hub. The .dynamictabs ancestor is what matters: the participants modal's tabs (nav nav-tabs without .dynamictabs) are not reached. This five-rule block (:7239-7271) is the only place in styles.css that touches .nav-tabs/.nav-link.
Two decisions an adversarial sweep forced (the card above already reflects them): the active tab's text is dark — #1d2125, Boost's grey palette, like core — not the accent blue: the accent stays in the 2px underline and the focus ring alone, because var(--bs-body-color) is undefined in Bootstrap 4 (Moodle 4.5) and blue as text fails AA in dark. And the base's border:0 + box-shadow knocked out core's keyboard focus ring (WCAG 2.4.7); :focus-visible restores an outline: 2px solid var(--bs-primary, #0f6cbf) with outline-offset: -2px (styles.css:7606-7614).
Not ported (decision closed): format_mtube's ResizeObserver-driven overflow dropdown — four measurement helpers that exist because mtube forces flex-wrap: nowrap on the tab strip inside the modal. Bootstrap's .nav is flex-wrap: wrap by default and the hub's strip is full-page: it wraps instead of overflowing, as the one above does if you narrow the window. Measured in this preview: one line down to a 420px container, two from 360px down, and zero horizontal overflow at any width. A search for ResizeObserver in amd/src/central/: no occurrences.
