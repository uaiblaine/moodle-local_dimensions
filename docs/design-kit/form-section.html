The heading is the name of a custom-field category, not a loose form string: core's instance_form_definition emits one header per category, and the plugin's handler passes the identifier through untouched so the name comes out verbatim (competency_handler.php:166-170, comment included).
There are two categories and both belong to the plugin. organize_customfield_categories() (helper.php:592-635) creates/reuses Feel (fieldcategory_feel) and Look (fieldcategory_look), moves each provisioned field into its own, deletes core's default category as soon as it is empty and orders Feel before Look — Look is last on purpose, because the built-in filemanagers are appended after the last category. The name is localised at creation time and the id is stored in cfcat_<slug>_<area> (helper.php:560-578), so a second pass in another language reuses the same category and an admin's rename survives.
The order within each section is that of the declared lists: feel_category_fields() (helper.php:509-521) and look_category_fields() (helper.php:532-543). Fields absent in the area are skipped — which is why the Feel section drawn above has four rows: the other five (Display mode, Accordion subline source, the template identifier and the two related-competency ones) belong only to the lp area (helper.php:456-463) and never reach the competency modal.
There is no colourpicker. custombgcolor and customtextcolor are text fields (displaysize 50, maxlength 255 — helper.php:240-260 and :269-289) and the user types the hex. Core has no colourpicker field type.
No asterisk anywhere: every plugin field is provisioned with 'required' => 0 (helper.php:128). The modal's required fields — shortname and idnumber, with addRule(… 'required' …) — are core fields, sit above these sections and do not belong to them.
Custom SCSS is only provisioned with enablecustomscss on (helper.php:487-490); the two image rows exist only in external mode (helper.php:473-478) — in built-in mode they are drawn by the picture_manager, see the Image dropzone card.
Pending — a description line per section. Core has no category description (a description is per field) and the plugin passes '' everywhere: the $description parameter of create_custom_field() (helper.php:106-113) defaults to '' at :112 and no caller fills it; the docblock at :93-95 itself recommends leaving it empty so as not to freeze a language. Today no description is rendered in this section.
