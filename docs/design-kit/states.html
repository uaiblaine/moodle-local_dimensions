Visible focus · :focus-visible → outline, not halo
outsideoffset 2px insideoffset -2px fieldSearch by name or ID number
The house pattern is outline: 2px solid #0f6cbf (or var(--bs-primary, #0f6cbf)) with outline-offset: 27 :focus-visible rules in styles.css write exactly that, plus 3 at 3px. The offset is 2px outside (19×) and -2px inside (11×) — inside when the target touches the container's edge and the outer ring would be clipped (the active tab, :7255-7259; the modal chip, :4955-4959). There is no box-shadow: 0 0 0 3px halo in the plugin. Where border: 0 kills Boost's native ring, the focus rule is restored explicitly — that is why the tab indicator got its own :focus-visible.
Loading / busy — the three shipped idioms
Core's tab switch already shows its own loading icon. What the plugin writes are these three, and each covers something different: the pane cover, the control that fired and the long-operation banner.
1 · The pane cover · reloadPane · aria-busy="true"
tabs.js:77-79 adds the class local-dimensions-central-tab-loading and aria-busy="true"; :103-105 removes both in the finally, and only if the reload's generation still owns the pane. The visual is a cover, not a replacement: an rgba(255,255,255,0.55) veil in ::before over the old content, a 2rem ring in ::after with its own keyframe (styles.css:4028-4069) — with no dependence on Boost's spinner-border. The veil is fixed white: the hub is a light surface only.
2 · The control that fired · disabled + fa-spin
⟳ the modal header's refresh chip
context.js:212-214 (the contextbar's refresh) and modal_refresh.js:74-75 (the modal header's refresh) do the same: button.disabled = true and icon.classList.add('fa-spin'), undone in a finally (:218-229 and :80-83). context.js also hands focus back to the button if disabling it dropped focus on the <body> (:226-228). The plugin's own styling here: a single line — .local-dimensions-modal-refresh[disabled] { cursor: default; } (styles.css:4962-4964). The rest of the disabled state is Boost's.
3 · Long-operation banner · spinner-border spinner-border-sm
Importing…
The only place Boost's spinner-border enters: central/download.js:53-58 (makeSpinner(), shared since 2026-07-28 — it used to sit in frameworks.js), consumed by the Structures import banner (frameworks.js:223, an alert alert-info with role="status" at :220), the Structures export loader (:284) and the Learning plans transfer (plans_transfer.js:181 export, :247 preview). Note the correct division of roles: the role="status" sits on the container and the spinner goes aria-hidden="true" — what announces is the text, not the ring. Putting both on the same element would cancel the role. The Structures export loader is the one place that does not hold up its end (no role, no text); plans_export.mustache:55-57 is the same control done right.
Mandatory discipline: clear the state in a finally, never only on the success path — otherwise a load that fails leaves the pane spinning forever, with no retry. Today there are 9 finally blocks in amd/src/central/: tabs.js:100, context.js:218, modal_refresh.js:80, frameworks.js:294, competency_links.js:488, related_competencies.js:199, enrol_methods.js:630, participants_users.js:113 and competency_tree_browser.js:274. downloadFramework() is the complete example: it re-enables the button, hides the loader and empties its content (frameworks.js:294-297).
House rule: pane reloaded → cover; row swapped in place → flash (see toast.html). The explicit escape hatch exists: reloadPane(pane, args, {quiet: true}) suppresses the cover, and today has a single caller — plans.js:103, the reload that preserves the scroll position.
This preview reproduces the keyframe and the prefers-reduced-motion rule because it does not load Boost. In the plugin this is written twice, on purpose: the cover carries its own (styles.css:4059-4069, 750ms → 1500ms under reduced-motion, mirroring Boost instead of freezing) and spinner-border inherits Boost's.
