The detail's body is three metrics, not count chips. structure_detail_content.mustache:75-111 draws Linked courses, Linked activities and Linked learning plans — each value is a <button data-action="show-usage"> that opens the usage modal (data-usage = courses / activities / templates), and becomes an inert <div> when linksclickable is false. Hence the underline on the value.
The header chips are these, all hidden until they have a value (:51-70): rule — the only chip-accent, with fa-check —, label (fa-tag), idnumber in monospace, scale, Tag 1 and Tag 2. The text comes out with a prefix: central_structure_rule = "Rule: {$a}" and central_plans_labelchip = "Competency label: {$a}"; the idnumber's prefix is the idnumber string from core, not from the plugin. The "label" chip is the Type custom field (competency_detail.js:161-168), and the rule only appears on a node with children and with a ruletype — a leaf never shows it (:152-154). There is no framework chip here: the coloured framework chip belongs to paginated-picker, where local_dimensions_search_competencies returns the source tag per result. The values above are real defaults — the shipped tag1_options is literally Edit me 1/2/3.
