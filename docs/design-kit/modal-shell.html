Design provenance: mtube: refresh mtube: expand mtube: footer links — all three are shipped.
The three controls are the same 1.75rem blue chip: refresh, expand/restore and close share background #e7f0f9, glyph #0f4d85 and hover #d4e6fb. Refresh and the size-toggles come from a combined rule (styles.css:5229-5253, hover :4947-4953); close is core's .btn-close restyled (:5074-5086, FA glyph \f00d at :5088-5096, hover :5098-5103). The values are literal, with no dark variant — the pair holds in both themes, which is why the chip here stays light blue in the dark preview too. Hover them: the hover above is the code's own. Neither of the first two carries .btn, so each draws its own focus ring (:focus-visible, styles.css:5255-5272).
Click ⤢ above — the icon becomes ⤡, and back. They are two buttons always present (fa-expand and fa-compress, inserted before the .btn-close at modal_expander.js:98-99); the CSS chooses which one shows (styles.css:5255-5280: .local-dimensions-modal-restore{display:none} + the two rules under .local-dimensions-modal-expanded), zero icon swapping in JS. In this preview the driver is a checkbox (:checked ~ .exp-out{display:none}); in production it is the local-dimensions-modal-expanded class on the .modal-dialog and the same pair of rules. The preview demonstrates the swap, not the width — the real dialog is what expands.
Expanded = real fullscreen (styles.css:5288-5312): width:100%, max-width:none, height:100%, margin:0, and square corners on the .modal-content/header/footer — it mirrors BS5's .modal-fullscreen without the class (4.5 has none) and without !important: 0,2,0 already beats modal-xl/modal-lg. It is 100% and not 100vw: the parent .modal is position:fixed and its width already excludes the scrollbar column, so the dialog sits beside it instead of running underneath (100vw includes the bar and would paint over the dialog's edge).
While refreshing the button is disabled and the fa fa-rotate icon spins — the fa-spin is added and removed by the JS (modal_refresh.js:75 and :82, cleared in a finally so a failure never leaves the button stuck); the CSS contributes only cursor:default in the disabled state (styles.css:5255-5272). The button is created at modal_refresh.js:36-48 (.local-dimensions-modal-refresh, data-action="modal-refresh") and anchored to the left of the size-toggles when they exist, otherwise to the left of the close chip (:67-68) — hence the order refresh, expand, close.
Footer — admin links on the left, primary action on the right
↗ Open scales page
Two mechanics, one single group. The group is always .local-dimensions-modal-footer-links with margin-right:auto (styles.css:5355-5361) — not justify-content-between: the auto-margin pushes any primary action to the right and works both in the empty footer and in the one that already has buttons, on BS4 and on BS5. The rule is scoped under .modal-footer to beat core's > *{margin} in any stylesheet order, and the btn-link gets a focus ring of its own (:5041-5045) because Moodle 4.5's BS4 forces box-shadow:none on it.
  • Participants (participants_manager.js:103-134): up to 4 destinations, each one behind a capability (ADMIN_PAGES, :57-66 — cancohortpage/canuserpage/canassignroles/canenrolpage), and the footer is per tab: only the active tab's link shows (showFooterLinkFor, :76-91, toggles the d-none by data-pane). When the active tab has no permitted link the footer collapses via .local-dimensions-modal-footer-empty (styles.css:5347-5361, display:none). This modal has no primary action — the footer is the link alone.
  • Framework form (frameworks.js:134-162, injectScalesLink): 1 link, with no per-tab logic (a form modal has a single panel), inserted as firstChild so the form's Save/Cancel stays on the right.
The links are a.btn.btn-link.p-0 + i.fa.fa-external-link.me-1, with target="_blank" rel="noopener noreferrer". In the participants modal the footer is born with no children; the group is appended before show() (participants_manager.js:185 awaited, :296 shows), so the hideFooter() core runs on show() finds a child and reveals the footer instead of applying .hidden.

Evidence of absence: grep -rn 'modal_expander\|modal_refresh' amd/src/ returns imports only in central/participants_manager.js:34-35, central/competency_links.js:41-42 and accordion.js:27 (the learner view, the expander alone) — the other 15 points (4 Modal.create, 6 ModalSaveCancel, 1 ModalDeleteCancel, 4 ModalForm) import neither of the two modules. The four ModalForm in particular could not take refresh without a reload callback, which attach requires.

The two halves are one single change

  • The header carries refresh and expand; that is why the administrative links live in the footer. With up to 4 destinations, a textual label next to three chips does not fit — and the footer is where an escape link belongs, away from the task's focus.

Three deliberate divergences — hub rules

  • Restyle core's .btn-close, never replace it. Swapping the element discards core's data-action="hide" and the accessible name it already brings. The chip is pseudo-element + Font Awesome because Moodle's stylelint forbids inline SVG in a data: URI.
  • The expanded state is a user preference, through local_dimensions/central/preferences (setUserPreference, debounce of 400ms — preferences.js:28, :36, :77), in the modalexpanded key inside PREF_DISPLAY (local_dimensions_central_display) — never sessionStorage. That way the choice follows the user across sessions and devices, and is shared by the two dense modals. (localStorage remains legitimate only for ephemeral pane geometry, as in pane_resizer.js:63/:69.)
  • Win by specificity, never by !important (declaration-no-important fails CI) — and no min()/max()/clamp() in length-valued properties (csstree/validator): use height/max-height pairs and calc().

The hooks: how each modal picks up the chip

  • There is no header-link class any more — grep -rn 'headerlink' amd/ templates/ styles.css classes/ lang/ returns zero.
  • The close chip arrives through two arms (styles.css:5374-5377): the participants modal and the links modal come through .modal:not(.local-dimensions-related-modal):has(.modal-body [class*='local-dimensions-']) .modal-header .btn-close (the body carries .local-dimensions-participants); the form modals (framework, competency, plan) come through .local-dimensions-central-page .modal-form-dialogue .modal-header .btn-close — the .modal-form-dialogue core puts on the dialog synchronously, before show(), so the chip paints from the first frame (without the flash :has() gives while it waits for the form's async body). The :not() excludes the Related competencies modal, which has a hidden header and uses core's close; the .modal-header stops a toast hosted in the body (the addToastRegion pattern) from getting the chip, which is wrong at its size.
  • .modal-title{flex-grow:1;min-width:0} is not decoration. Core gives margin-left:auto to the .btn-close, which on its own strands the size-toggles next to a short title. The rule is keyed on the expander's own button — .modal-header:has(.local-dimensions-modal-sizetoggle) .modal-title (styles.css:5313-5324) — covering the participants and links modals without depending on any class on the dialog.
  • The same .local-dimensions-modal-sizetoggle marker also scopes the overflow:hidden that kills the second scrollbar of those two modals (styles.css:5218-5224) — filepicker, TinyMCE and the hub's confirms stay out.
