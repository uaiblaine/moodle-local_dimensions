Evidence hub mockups

Eight screens of the proposed companion plugin: the readiness list, the matrix, the inspection drawer, the worker's evidence form, the validity policies, the dossier export, the dossier PDF and the public verification page. They draw in Boost's own palette, like the Competency hub design kit, and every number is example data for one fictional contract. The numbered notes tie each screen to a decision or a core API in README.md.

  1. The filter is the plan template, read as the contract's competency matrix. Users are the owners of active plans made from it (D5).
  2. Readiness counts a worker as ready when every required competency is Compliant or Due. One grouped query over the same base as the grid; the two never disagree.
  3. The grid pages in two steps: sort the narrow key, then load one page's details. The S0 spike measured a report builder system report at 0.5–0.8 s on 10,000 workers × 30 competencies, the two-step query under 300 ms on PostgreSQL and MariaDB. Download goes through core's dataformat API.
  4. Evidence types flagged sensitive (ASO) hide their details without viewsensitive, and their files stay out of dossiers by default (D7).
  5. An unverified new certificate does not count for a regulatory policy, so the old one still drives the status until someone verifies the new one (D4).
